# Security Policy

## Supported versions

Security fixes are prioritized for the latest release and the default development branch.

## Reporting a vulnerability

Do not disclose security vulnerabilities in public issues, pull requests, chat messages, or documentation.

Report vulnerabilities privately through the repository's security advisory feature or the project's official maintainer contact channel.

Include:

- A clear description of the vulnerability.
- The affected component and version or commit.
- Reproduction steps or a proof of concept.
- The expected and observed behavior.
- Any suggested mitigation.

Please remove credentials, personal data, customer data, and production tunnel details from reports.

Maintainers will acknowledge a valid report, assess its impact, coordinate a fix, and publish release guidance when disclosure is safe.

## Scope

Reports involving the tunnel relay, tunnel agent, CLI, dashboard, desktop app, public API, protocol, authentication, routing, credential handling, or deployment configuration are in scope.

Denial-of-service reports, exposed test credentials, unsupported versions, and vulnerabilities requiring a compromised host should include a clear impact assessment.
