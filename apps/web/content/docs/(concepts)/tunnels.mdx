A tunnel is a durable control-plane resource. It has an owner organization,
a protocol, a local target, and a lifecycle state. A session is the live
connection between a client and the relay.

The control plane records tunnel identity, access settings, limits, and usage
metadata. The relay owns live connections and data-plane forwarding. This
separation lets the API and relay scale independently.

## Supported client protocols

- `http` forwards HTTP requests to a local HTTP server.
- `https` represents an HTTPS local target when configured by the client.
- `tcp` forwards raw TCP streams.
- `udp` is reserved for the datagram transport and should not be documented as
  generally available until the relay deployment enables it.

## Lifecycle

The important states are `creating`, `connecting`, `active`, `disconnected`,
`expired`, and `revoked`. A disconnected session can reconnect while its
tunnel remains valid. A revoked or expired tunnel cannot be reopened.
